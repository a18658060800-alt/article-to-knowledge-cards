# make-knowledge-cards

把一篇文章变成 5~8 张真正值得复习的知识卡片。

## 1. 项目解决什么问题

读长文时，真正难的不是“读完”，而是把重要内容变成可复习、可调用的知识。手动做笔记容易变成逐段摘要或金句摘抄；直接让 AI 总结又常出现重点分散、卡片重复，甚至补充原文没有的信息。

`make-knowledge-cards` 是一个 Agent Skill，用来把文章压缩成少量、独立的知识卡片：一张卡片只讲一个知识点，读完能自测，回到原文也能核对。

## 2. 主要功能

- 从粘贴的文章或本地 `.md` / `.txt` 文件中提取 5~8 个重要知识点，生成知识卡片。
- 每张卡片包含：标题、核心知识、简明解释、例子或自测问题。
- 先合并重复内容，再确定卡片数量；一张卡片只讲一个知识点。
- 解释只压缩、改写原文，不补外部知识；原文没有合适例子时改用自测。
- 原文信息不足时按实际数量输出，不强行凑满 5 张。
- 中文文章输出中文卡片，英文文章输出英文卡片，结构标签随语言切换。
- 不支持网页抓取、PDF、Anki、图片识别和图形界面；这些内容需要先转成纯文本。

## 3. 安装方法

1. 获取本项目中的 `skills/make-knowledge-cards` 目录。
2. 把整个目录放入运行环境的技能目录：
   - DSH：`~/.dsh/skills/`（Windows 下为 `%USERPROFILE%\.dsh\skills\`）
   - 其他支持 `SKILL.md` 的 Agent Skills 环境：放入其 skills 目录。
3. 重新加载技能（重开会话，或按运行环境的方式刷新），使 `SKILL.md` 生效。

安装后的目录结构：

```
skills/
└── make-knowledge-cards/
    ├── SKILL.md
    └── agents/
        └── openai.yaml
```

临时使用也可以：把 `SKILL.md` 的内容直接提供给 Agent，并要求它按此执行。

## 4. 使用方法

在对话中直接描述任务，或显式点名技能：

```text
用 make-knowledge-cards 把下面这篇文章做成知识卡片：

<粘贴文章正文>
```

```text
把 notes/attention.md 转成知识卡片，只保留最重要的 6 个点。
```

```text
这篇比较短，有几张做几张，不要凑数。
```

使用说明：

- 一次处理一篇文章或一个 `.md` / `.txt` 文件；有多个文件时先指定其中一个。
- 如果文章信息不足，技能会少做几张，并在末尾说明原因。
- 如果输入是 PDF、网页、Anki 或图片，技能会提示先转成纯文本，而不是自行抓取或解析。

## 5. 输入输出示例

### 输入（节选）

```markdown
# 为什么复盘总流于形式

复盘失败往往不是因为不认真，而是因为流程太复杂。把复盘压缩到固定时间、回顾事实、做一次调整，才更容易坚持。

固定时间：把复盘写进日历。不要等“有空再做”，因为永远不会有空。

回顾事实：只写本周完成了什么、没完成什么、临时插入了什么，不写“我真没用”之类的评价。评价会让人防御，事实才能带来调整。
```

### 输出（节选，完整输出为 3 张）

```markdown
# 知识卡片：为什么复盘总流于形式

## 1. 复盘失败往往是因为流程太复杂

**核心知识：** 周复盘坚持不下来，常见原因不是不认真，而是流程太复杂。

**简明解释：** 原文把复盘压缩成固定时间、回顾事实、做一次调整等少数步骤，认为流程越简单越容易坚持。

**自测：** 按原文，周复盘失败最常见的原因是什么？
**参考答案：** 不是不认真，而是流程太复杂。

## 2. 把复盘写进日历，才会变成习惯

**核心知识：** 复盘时间要提前固定在日历里，不能等“有空再做”。

**简明解释：** 原文的理由很直接：不要等“有空再做”，因为永远不会有空。时间固定后，复盘才会变成习惯，而不是额外的任务。

**自测：** 为什么不能等“有空再做”？
**参考答案：** 因为永远不会有空；时间固定后，复盘才会变成习惯。

说明：原文可支撑的独立知识点为 3 个，未凑满 5 张。
```

> 已通过官方 `skill-creator` 的 `quick_validate.py` 校验：`Skill is valid!`
